====================================================
1. PROJECT VISION
====================================================

The project is an Android-based AI assistive application designed to help visually impaired users independently understand their surroundings, navigate safely, interact with the application through voice, receive intelligent contextual guidance, identify Indian currency, and request emergency assistance.

The application is primarily designed for hands-free interaction.

The user should be able to speak commands such as:

"Start navigation"
"What's in front of me?"
"Read this"
"Identify this currency"
"Help me"
"Stop navigation"

The application should understand the command, activate the appropriate module, process camera/location/sensor data, and provide the result through Text-to-Speech.

The application will have a visual UI for partially sighted users and development/debugging purposes, but all important functionality must also be accessible through voice interaction for completely blind users.

====================================================
2. APPROVED PROJECT OBJECTIVES
====================================================

These are FINAL and approved by my project guide.

Objective 1:
To enable hands-free voice interaction using Android Speech Recognition and Text-to-Speech, allowing visually impaired users to naturally communicate with and control the application through voice commands.

Objective 2:
To provide real-time environmental perception and navigation using GPS, CameraX, and computer vision techniques for object detection, scene understanding, OCR, and Indian currency recognition, helping users navigate safely and understand their surroundings.

Objective 3:
To implement a context-aware AI engine using computer vision and lightweight AI models to interpret the user’s surroundings, make situation-based decisions, and provide clear and explainable guidance in natural language.

Objective 4:
To facilitate emergency assistance through Android location and communication services, enabling users to quickly send SOS alerts with their location to predefined emergency contacts when required.

4. IMPORTANT PROJECT PHILOSOPHY
====================================================

The project should NOT be treated as four completely independent applications.

It is ONE integrated assistive Android application containing multiple AI and accessibility modules.

The central interaction flow is:

USER
 ↓
VOICE COMMAND
 ↓
ANDROID SPEECH RECOGNITION
 ↓
COMMAND / INTENT UNDERSTANDING
 ↓
APP DECIDES WHICH MODULE TO ACTIVATE
 ↓
CAMERA / GPS / OTHER INPUT
 ↓
AI / ML PROCESSING
 ↓
RESULT / CONTEXT
 ↓
CONTEXT-AWARE ENGINE
 ↓
NATURAL LANGUAGE RESPONSE
 ↓
TEXT-TO-SPEECH
 ↓
USER

Example:

User:
"Start navigation"

System:
1. SpeechRecognizer converts speech to text.
2. Command/intent layer identifies "navigation".
3. Navigation module starts.
4. CameraX continuously provides camera frames.
5. Object detection identifies objects.
6. GPS provides location.
7. Scene understanding processes the environment.
8. Context-aware engine combines these inputs.
9. It determines appropriate guidance.
10. Text-to-Speech speaks the guidance.

Example response:

"Continue straight. There is a person approximately three meters ahead."

====================================================
5. CONTEXT-AWARE AI ENGINE
====================================================

The Context-Aware AI Engine is the decision-making layer of the project.

It should NOT simply describe what is visible.

It should use environmental information and user/navigation context to determine what action or guidance is useful.

Example:

Computer Vision:
"Person detected."

Context Engine:
- Person detected
- Person is moving toward the user
- User is walking forward
- Distance is decreasing

Possible decision:
"Someone is approaching you from ahead. Please slow down."

Another example:

Object detector:
"Stairs detected."

Context:
- User is navigating forward
- Stairs are directly ahead

Guidance:
"Stairs are ahead. Please proceed carefully."

The context engine can initially be rule-based or hybrid rather than requiring a huge VLM.

The architecture should preferably be:

Perception
+
Context
+
Rules / lightweight AI
+
Decision
+
Natural-language generation
+
Text-to-Speech

Avoid unnecessarily using expensive cloud VLM APIs for every camera frame.

====================================================
6. AI/ML STRATEGY
====================================================

The project should prioritize lightweight/local AI models wherever practical.

Potential models/technologies include:

- YOLO / YOLO-family models for object detection
- Mobile-friendly computer vision models
- OCR engines such as ML Kit Text Recognition or Tesseract where appropriate
- Lightweight scene understanding models
- SmolVLM / SmolVLM2
- Qwen2.5-VL-3B if hardware allows
- Moondream
- TensorFlow Lite / LiteRT or ONNX Runtime Mobile for on-device inference where suitable

Do NOT automatically recommend a large cloud VLM.

Whenever suggesting a model, evaluate:

1. Accuracy
2. Model size
3. RAM usage
4. Inference latency
5. Android compatibility
6. Offline capability
7. Battery consumption
8. Ease of integration

The goal is a practical final-year project prototype, not a massive commercial AI system.
